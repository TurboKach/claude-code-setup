# Subagent no-background: timeout default, PreToolUse hook, doctrine fix

Feature base: `51d3cd9` (master). Executor for every step: **the master, inline** — owner waiver 2026-09-04 ("you can do it in master session as there is not so many code changes"). The codex gate still runs on the whole range.

## Context

2026-09-04, clipsy_ios side-handle arc (Claude Code 2.1.260): after the master reported "all done" the owner found one live shell. It was a `until [ -f <task>.output.done ]; do sleep 5; done` loop the `fixer` subagent had started as a `run_in_background` Bash 54 minutes earlier. Chain: `xcodebuild test` with no `timeout` → auto-backgrounded at the 2-min default → `sleep 90; tail` blocked by the harness with "use Monitor with an until-loop" → the kit's `tools:` list strips Monitor and TaskStop → the agent hand-rolled a background poll on a marker file the harness never writes → with fork mode on (default since 2.1.232) the agent is a background subagent, whose background commands keep running past its final response (tools-reference), uncapped since 2.1.257.

Measured over 8 clipsy sessions since 2026-08-25: 25 subagents hit auto-backgrounding, ~30 of ~40 of those calls passed no `timeout` despite the agent-definition line; 16 hit the sleep block; 2 orphaned pollers; 5 more foreground `.output.done` polls burned their full 5–10 min timeout. Prose does not prevent this; the fix is mechanical.

Doc facts (code.claude.com, 2026-09-04): `BASH_DEFAULT_TIMEOUT_MS` is the default when Claude passes no timeout (120000); the ceiling is the larger of it and `BASH_MAX_TIMEOUT_MS`. settings.json `PreToolUse` hooks run before every tool a subagent uses; hook input carries `agent_id`/`agent_type` only inside a subagent; Bash `tool_input` has `command`, `timeout`, `run_in_background`; deny = `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"…"}}`. `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS` is rejected: it would also kill the master's backgrounded codex run.

## Changes

**1. `hooks/subagent-no-background.sh` (new).** PreToolUse on Bash, JSON on stdin, python3 for parsing (install.sh already requires it). Never blocks on its own failure: empty/malformed stdin, missing python3, non-Bash tool → exit 0 with no output. Two rules, both emitting the documented deny JSON on stdout, exit 0:
- **A. subagent + `run_in_background: true`** (i.e. `agent_id` present) → deny. Reason text tells the agent the pattern: run in the foreground with an explicit `timeout` sized to the run (default now 15 min); if a command was already auto-backgrounded, wait in the foreground with `until ! pgrep -f '<pattern>' >/dev/null; do sleep 10; done` under its own `timeout`, then read the task output file; a subagent's background commands outlive its final report and nobody stops them.
- **B. any `command` matching the loop shape `(until|while)\b.*output\.done`** (master or subagent) → deny: the harness never writes that marker, so the loop runs until its timeout or forever. Matching the loop shape, not the bare string, keeps transcript-forensics greps and heredocs that mention the marker allowed (the kit has no legitimate use of the marker; reviewer grep confirmed).
Header comment states the incident, the two rules, and the fail-open policy, in the style of `hooks/stack-update-check.sh`.

**2. `hooks/tests/subagent-no-background.test.sh` (new).** Plain-bash, no framework, same shape as the retired `hooks/tests/codex-runner-hooks.test.sh` (`git show 6e37bf6^:hooks/tests/codex-runner-hooks.test.sh`): PASS/FAIL per case, exit non-zero on first failure. Cases: subagent+bg → deny JSON; subagent, bg false/absent → silent allow; master+bg → allow; `.output.done` poll in master → deny; `.output.done` poll in subagent, foreground → deny; `tool_name: Read` → allow; empty stdin → allow; malformed JSON → allow. install.sh's `hooks/*.sh` glob does not descend into `hooks/tests/`, so the test is never installed.

**3. `settings.example.json`.** `env.BASH_DEFAULT_TIMEOUT_MS: "900000"` (15 min; clipsy suites run 5–9 min; the ceiling follows automatically, so `BASH_MAX_TIMEOUT_MS` stays unset). New `hooks.PreToolUse` group: matcher `"Bash"`, command `~/.claude/hooks/subagent-no-background.sh`, timeout 5.

Same shape guards and `norm_path` idempotency check per event, same warning-instead-of-abort policy, warning text names the event. New argv for the second hook path; `merged_desc`/print lines mention both hooks. Header comment (lines 4–14) gains one clause for the PreToolUse hook and the timeout default. The env `setdefault` loop already installs the new env key — no change there.
